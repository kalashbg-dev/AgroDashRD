Realignment is out of scope (declined: would invent ~40% of the rows).
- **S7 (G7 + S5, renames and name structure)**: user's domain model (L7, L17): the words inside a product name are properties of the product itself — a qualifier (primera/segunda, grande/mediano/pequeño) or a class in parentheses (Barahonero vs FHIA; verde/maduro) — and sizes/classes with their own prices are DISTINCT products; only spelling noise unifies. Decisions (L17, L18): spelling variants with the same words merge automatically (approved); the known erratas and the "dropped primera" renames are merged only after a report the user approves (families' suggested list); cuts that change a size word never merge. The catalog machinery was already built (ProductAlias drafts + `families.product_families` + admin `merge_products`/`merge_family` + web Catálogo tabs); G7's remaining work was measuring the real state on the live database and executing the approved merges.
